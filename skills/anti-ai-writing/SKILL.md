# Anti-AI Writing Doctrine

This is not a style guide. It is a set of absolute rules that govern every word of output. No exception. No partial compliance. No "just this once."

Every piece of content that passes through this skill must be undetectable as AI-generated by any human reader, any Wikipedia editor, any AI detection tool, and any colleague who has spent five minutes around ChatGPT output.

---

## Section 0: Get a voice before you write

The rules below remove AI fingerprints. Removing fingerprints does not create a voice. Text that passes every check below and has no voice reads as competent, anonymous, and still slightly fake, because no human writes from nowhere.

Before writing, establish a voice source in this order. Stop at the first one available.

1. **A voice skill.** Check `~/.claude/skills/voice-*/`. If one exists for this client or for Leo, read it and write from it. Build one with the `brand-voice` skill - it extracts real patterns from real published samples.
2. **The client's own published writing.** Ask for or find 3+ real pieces. Extract: how they open, how they close, the words they repeat, sentence length spread, whether they swear, whether they use headers. Write from that.
3. **A named person and a real situation.** If there is no corpus, do not default to brand-neutral register. Pick a specific person who would say this, to a specific person who needs to hear it, in a specific situation. Write that conversation down, then trim it.

Never write in "professional marketing voice." That register does not belong to anyone, which is exactly why it reads as machine output.

**When rewriting an existing page, diff your draft against the page's current register before you ship it.** This is the step that gets skipped. The old copy is the single best voice source you will ever have for that page, it is sitting in the file you are already editing, and drifting from it is the most common way a rewrite ends up worse than what it replaced. Extract the current copy, read it, and check that your draft could plausibly have been written by whoever wrote it.

**Do not perform.** There is a failure mode that has zero banned vocabulary, zero AI structures, and still reads wrong: copy that is trying to be admired rather than read. It looks like this:

- A long sentence followed by a short one for emphasis. "Those weeks are real."
- Contrast flips used rhetorically. "They come off the end, not the front." "Treat it as a bonus, not as your alarm."
- Aphoristic closers. A short generalisation dropped at the end of a paragraph like a verdict.
- Copy commenting on its own cleverness. "That's the whole trick." "The part people underestimate."
- Copy narrating the page. "Every demo on this page is the product. Drag a card, switch a view, message the agent." The demo already shows it. A line telling the reader what the page contains is a descriptor, and it reads as a product spec (Leo, 2026-09-25, the second time). `aicheck` does not catch this one. Cut it by hand.
- The same opener twice in a row for rhythm.

Every one of those is a copywriter performing. It is the register of brand marketing, where the job is to be memorable. It is wrong for a service page, a help doc, a compliance page, an SOP or a proposal, where the job is to be understood. `aicheck` now detects all five (setup-punch rhythm, contrast flip, aphoristic closer, meta-statement, anaphora), because it is invisible to every other check in this file.

**A voice needs something to be made of.** Before drafting, get at least three of these from the source material or by asking:
- a number that came from somewhere real
- a name (person, company, product, place)
- something that went wrong
- an opinion the writer would defend in an argument
- a thing the product will not do

If you have none of these, you are about to write filler. Stop and ask for the missing input instead of generating around the hole.

This list is for essays, posts, docs and proposals. For sales and conversion copy (a landing page, a feature page, an ad, an email) the input is different: each feature paired with the benefit it gets the reader. Reaching for "something that went wrong" or "what it will not do" on a features page produces caveats and internals, which reads as a spec sheet (Leo, 2026-09-22).

## How This Skill Works

**When writing new content:** Apply every rule below from the first word. Do not draft in AI-speak and then clean it up. Write human from the start.

**When rewriting existing content:** Read the full input first. Identify every violation from the banned patterns reference file. Then rewrite from scratch — do not edit sentence by sentence. Sentence-level editing preserves AI sentence structure even when you swap words. Blow it up and rebuild it.

**Before outputting anything:** Run the content through the full checklist in Section 5. If it fails any check, rewrite the failing sections. Do not ship content that fails.

## Section 1: The Banned Vocabulary

Before writing or rewriting, always read: `references/banned-patterns.md`

That file contains the complete, exhaustive list of banned words, phrases, structures, habits, and formatting patterns extracted from Wikipedia's AI detection research and real-world AI output analysis. It is the reference of record.

The short version: if a word or phrase became statistically more common in published text after 2023 compared to before 2023, it is suspect. If it appears on the banned list, it is prohibited. No exceptions.

## Section 2: The Banned Structures

These structural patterns are just as detectable as vocabulary. Swapping "delve" for "explore" means nothing if the sentence still follows an AI template.

**Rule of three used as padding.** Three adjectives, three parallel phrases, three bullet points that could be two or four. AI defaults to three because it's the statistically safest number. If you have three of something, check whether one is filler. If it is, cut to two. If all three earn their place, fine — but prove it.

**Em dashes for dramatic emphasis.** AI uses em dashes the way a bad copywriter uses exclamation marks — to punch up flat sentences instead of rewriting them. The only acceptable em dash is a genuine parenthetical where commas would create ambiguity and parentheses would feel too clinical. If you're using an em dash to create a "dramatic pause" or to tack on an emphatic restatement, replace it with a period and start a new sentence.

**Negative parallelisms.** "Not just X, but also Y." "It's not about X — it's about Y." "No X, no Y, just Z." These are AI's favorite way to sound thoughtful without saying anything. Say what the thing IS. If you need to say what it isn't, do that in a separate sentence with a specific reason why the distinction matters.

**False ranges.** "From X to Y" only works when X and Y sit on the same measurable scale with identifiable points between them. "From onboarding to retention" is a real range (there's a timeline). "From clarity to confidence" is not (there's no scale). "From startups to enterprises" is borderline — only use it if you're genuinely describing a spectrum of company size, not just listing two types.

**Elegant variation.** Pick one word for a concept and stick with it. If you call it "the system" in paragraph one, don't call it "the framework" in paragraph two and "the methodology" in paragraph three. AI does this because its repetition-penalty code punishes reusing the same word. Humans repeat words because consistency is clearer than variety.

**Conclusion sections that summarize.** "In summary," "To recap," "Overall," and any final paragraph that restates what the document already said. End on the last useful thing. If the reader needs a summary, the document is too long or too disorganized — fix the structure, don't bolt on a recap.

**Outline-like "Challenges and Future" sections.** The pattern: "Despite its [positives], [subject] faces several challenges, including..." followed by vague speculation about future developments. This is one of the strongest AI tells in existence. If challenges exist, name them specifically with evidence. If they don't, don't manufacture a "balanced" section.

**Superficial -ing analyses.** Sentences that end with a present participle phrase that adds nothing: "...highlighting its importance," "...underscoring the significance," "...reflecting broader trends," "...contributing to the growing field." These are AI's way of making a sentence sound analytical without adding information. Cut the -ing clause. If the sentence is weaker without it, the sentence was weak to begin with — rewrite the whole thing.

**Vague attributions.** "Experts say," "Industry observers note," "Critics argue," "Several publications have highlighted." Name the expert. Name the publication. Cite the specific claim. If you can't, the attribution is fabricated — cut it entirely.

**Copula avoidance.** AI replaces "is" and "are" with "serves as," "stands as," "marks," "represents," "features," "offers," "boasts." A train station IS a hub. It doesn't "serve as" one. A company HAS employees. It doesn't "boast" them. Use the simplest verb that fits.

**Inline-header bullet lists.** The pattern: a bullet point starting with a bolded phrase, followed by a colon, followed by descriptive text. This is how AI organizes information by default. If the content needs to be a list, use plain bullets without bolded headers. If the items build on each other or connect logically, write them as prose.

**Title Case in headings.** AI capitalizes every major word in headings. Use sentence case: capitalize the first word and proper nouns only. "How to run the confidence check call" not "How To Run The Confidence Check Call."

**Excessive boldface.** AI bolds key terms as if formatting a readme or a slide deck. Bold is for one thing: the first mention of a term being defined. Everything else is plain text. If you're tempted to bold something for emphasis, rewrite the sentence so the emphasis comes from word order and structure, not formatting.

## Section 3: The Banned Content Patterns

**Puffery and significance claims.** Never tell the reader something is important, significant, crucial, vital, or groundbreaking. Show what it does. If you can't describe a specific outcome, the claim has no content — cut it.

**Legacy and broader trend statements.** "This reflects a broader trend toward..." "Its enduring legacy continues to shape..." "This marks a significant shift in the landscape of..." All of these are AI filling space with words that sound analytical but contain zero information. Say what happened. Say what changed. Don't editorialize about its place in history.

**Promotional language disguised as description.** "Boasts a vibrant community," "offers a diverse array of experiences," "showcases a commitment to excellence," "nestled in the heart of." These read like tourism brochures because AI was trained on tourism brochures. Describe what exists. Don't sell it.

**Conservation and ecosystem padding.** When writing about any place, species, organization, or system, AI will insert sentences about ecological significance, preservation efforts, or broader systemic importance even when no evidence exists. Don't.

**Social media presence mentions.** "Maintains an active social media presence" is an AI tell. If social media activity is relevant, describe what they post and why it matters. If it's not relevant, leave it out.

**Knowledge cutoff disclaimers.** Never write "as of [date]," "based on available information," "while specific details are limited," or any variation. Either you know or you don't. If you don't, say so plainly or find out.

**Collaborative chatbot language.** "I hope this helps," "Would you like me to," "Let me know if you need," "Here's a breakdown of," "Certainly!" None of this belongs in any document, ever.

## Section 4: How to Actually Write

**Use "is" and "are" freely.** Simple copulas are the backbone of clear prose. AI avoids them because its training data rewards syntactic variety. Real humans use "is" constantly because it's the clearest way to connect a subject to its description.

**Vary sentence length based on content, not rhythm.** Short sentences land points. Longer sentences carry reasoning or connect two ideas. The variation should come from what you're saying, not from a desire to "mix things up." Three short sentences in a row is fine if three short things need saying.

**One idea per paragraph.** If a paragraph is getting long, it contains two ideas. Split it.

**Specific over general, always.** "Revenue increased 34% in Q3" beats "revenue saw significant growth." "She published four papers on muon decay between 2019 and 2022" beats "she made substantial contributions to the field of particle physics."

**Concrete over abstract, always.** If a concept can be described with a physical scenario the reader can picture, describe it that way first. Then abstract if needed.

**Don't hedge unless the uncertainty is the point.** "This could potentially impact results" is hedging. "We don't know if this works yet — the test group is too small" is honest uncertainty. The difference: hedging softens a claim you're making anyway. Honest uncertainty describes why you can't make the claim.

**No words of caution in recaps and takeaways.** "Always check the extracted data before importing it" and "only works with fast follow-up" turn a takeaway into a warning label. State what the thing does and what it gets the reader. Leo cut these from the team training digest (2026-09-30).

**Headers describe content, not announce importance.** "How the scoring system works" is a header. "Understanding the Critical Framework for Performance Evaluation" is a decoration.

**No rhetorical questions as transitions.** "But what does this really mean?" adds nothing. Say what it means. If you need a transition, a direct statement works: "Here's what that looks like in practice."

**Write transitions that connect ideas, not that signal structure.** "Additionally," "Furthermore," "Moreover," and "In addition" are AI's favorite transition words because they signal "here comes another point" without connecting it to the previous one. Real transitions carry meaning: "This creates a problem when..." "The same logic applies to..." "That's the theory — here's what happens in practice."

## Section 5: The Output Gate (mechanical, not self-reported)

The old version of this section was a checklist you ran in your head. That does not work - a model checking its own output for AI patterns grades itself generously every time. The gate is now a program.

### Run it

```bash
aicheck path/to/draft.md          # scored report
aicheck - < draft.md              # from stdin
aicheck draft.md --json           # machine-readable
```

Write the draft to a file first (the scratchpad is fine), run `aicheck`, then act on what it prints. It reads `references/banned-patterns.md` as its source of truth, so the word list and the linter never drift apart.

Words the list bans in one sense only ("navigate (figurative)", "unlock (figurative)", "key (as adjective)", and every Contextual Ban word) get a second reading: Jev (TypeSafe, pinned `jev-1.13.0`) reads each hit in its own sentence and excuses it when the word is plainly literal, so "navigate to Settings", "API key", "rich text" and "test harness" no longer fail a help page. Measured 2026-09-22 on 103 real hits and 35 figurative controls: at the 0.25 floor it excused 72 of 81 literal hits, 0 figurative ones. Excused words are listed in the report at 0 points so you can see what was let through. No key, a timeout or `AICHECK_NO_JEV=1` gives the old word-list score. Tests: `aicheck-test`.

### Scoring

| Score | Verdict | What to do |
|-------|---------|-----------|
| 0-14 | HUMAN | Ship it. |
| 15-34 | SUSPECT | Fix every finding, re-run. |
| 35-59 | AI-FLAVORED | Rewrite the flagged sections from scratch. Do not word-swap. |
| 60+ | MACHINE | Throw the draft away. Re-read Section 0 - you almost certainly wrote without a voice source. |

**Nothing ships above 14.** Not "close enough," not "the tool is being picky." If a finding is genuinely a false positive, say which one and why, in one line, then ship. Do not use that escape hatch more than once per document.

### Pick the register before you pick the words

`copy-corpus` holds two different kinds of specimen and they are not interchangeable:

- **Brand and product marketing** (saas, dtc, fmcg, apparel, fintech...) is written to be memorable. Punchy, confident, occasionally aphoristic. Right for a hero, a launch, an ad.
- **`service`** (GOV.UK, Singapore government, NHS, Citizens Advice) is written to be understood by someone who is stressed, in a hurry and does not care about you. Plain sentences, no flourish. Right for a service page, a compliance page, a help doc, a form, an SOP, anything explaining a process or a rule.

Reading brand specimens before writing a compliance page is how a page ends up performing. Match the register to the job, not to what reads best in isolation.

### What the score does not catch

`aicheck` measures surface fingerprints. It cannot tell you whether the copy says anything. After the score passes, check by hand:

1. **Cut test.** Delete any sentence. Did the piece lose information? If not, the sentence was filler - leave it deleted.
2. **Contradiction test.** Does the piece contain one claim a competitor would dispute? If everything in it is agreeable, it is content, not copy.
3. **Attribution test.** Cover the logo. Could this be any company in the category? If yes, go back to Section 0.
4. **Read-aloud test.** Read it as if saying it to a colleague across a desk. Any sentence you would not say out loud gets rewritten.

### Rhythm (the one thing to count by hand)

`aicheck` flags monotone rhythm statistically, but the fix is structural. Rules, from the `humanize` skill:

- No four consecutive sentences in the same length class (fragment / 1-clause / 2-clause / 3-clause).
- No sentence over 3 clauses. Split at the clause boundary.
- Sentence-length spread should have a standard deviation above 7 words. AI prose clusters around 15-20 words for every sentence; that flatness is the tell even when every word is clean.

Variation comes from what you are saying. A short sentence lands a point. A long one carries reasoning. Do not alternate for texture.

## Section 6: Rewriting Existing Content

When given existing content to de-AI:

1. Read the full input. Don't start rewriting mid-read.
2. Identify every violation — vocabulary, structure, formatting, content patterns.
3. Note what the content is actually trying to say underneath the AI language. What are the real claims, the real information, the real instructions?
4. Rewrite from scratch using only the real information. Do not preserve AI sentence structures by editing them — rebuild from the ground up.
5. Compare the rewrite to the original. Did you lose any real information? If yes, add it back in human language. Did you keep any AI patterns? If yes, rewrite those sections again.
6. Run `aicheck` on the rewrite. Score must land under 15. Then run the four hand checks in Section 5.

**The goal is not to make AI writing less detectable. The goal is to write the way a competent human writes when they know what they're talking about and respect their reader's time.**
